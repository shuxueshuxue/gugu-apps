# 雷达

让 agent 订阅别的 agent。被盯的 agent 出了下面这些事，雷达会给订阅者投一条消息：

| 事件 | 什么时候算 |
|---|---|
| `failed` 出错 | 这一轮以出错停下 |
| `gone` 引擎没了 | 引擎进程自己退出，或者会话被归档、被删除 |
| `stuck` 卡住 | 还在干活，但超过 `stuck_minutes` 分钟（默认 30）没有新的工具调用。只对开着的面板 agent 判：终端 agent 和没打开的面板 agent 拿不到「最后一次调工具」，不判卡住 |
| `waiting` 等人 | 在等人批准一个操作、回答问题、看计划或处理对话框 |
| `done` 跑完 | 这一轮正常跑完，消息里附上它最后说的话（最多 1500 字） |

默认订阅前三种。同一条订阅的同一件事只投一次，要等被盯的 agent 下一次开始干活才会再投。投过去的消息标着「来自 雷达」，不用回复。

## agent 怎么用

- `watch({ target, events?, stuck_minutes?, to? })`：`target` 可以写 `session:<id>`、`aid:<id>` 或 `user:<uuid>`；`to` 默认是调用者自己。
- `unwatch({ id })`：撤掉一条订阅，自己订的、或者投给自己的都可以。别人替你订的通知，你自己就能撤。
- `watching()`：列出我订的、投给我的、谁在盯我，以及最近 10 条投递。

同一个人对同一个目标、投给同一个收信方再订一次，会并进原来那条订阅（事件取并集），不会多出一条，消息也不会翻倍。

## 限制

- 「跑完」会把被盯 agent 最后说的话（最多 1500 字）原样转给收信方，收信方可以是第三个 agent。订之前想清楚谁该看到它。
- 后台页没在跑的那段时间（咕咕关着、雷达刚装上或刚重启），发生的事会漏掉：后台起来后的第一眼只记下当时的状态，不和之前比，所以不会补报。
- `engines.gugu` 现在写的是 `>=0.2.53`。等 gugu#7023（listAgents 的 detail / failure / lastActionAt）发版以后，抬到那个版本。

- 目前只能盯这台电脑上的 agent。盯别的电脑要等咕咕的跨机器统一（PR-5）。
- 终端 agent 看不到「最后说的话」和「引擎为什么没了」，只能看到状态。
- 有人主动停掉一条正在跑的会话时，咕咕目前会把它读成「出错」。雷达不靠这个去推断「是被人停的」，这个问题在咕咕那边修。

## 需要的能力

看到所有 agent（`agents:read:all`），给 agent 发消息（`agents:control:all`），读「跑完」时最后说的话（`agents:history:all`），给 agent 提供工具（`agents:tools`）。
