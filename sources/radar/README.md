# 雷达

让 agent 关注别的 agent。被关注的那个出了事，雷达给收提醒的人发一条消息。关注分三档，每一档都包含前一档：

| 档位 | 什么时候提醒 |
|---|---|
| `trouble`（默认） | 它停下来报错了；它不在了（引擎意外退出，或者任务被归档、删除）；它好像卡住了：还在干活，但 `stuck_minutes` 分钟（默认 30）没有新动作。卡住只对开着的面板 agent 判，终端 agent 和没打开的面板 agent 看不到最后一次动作，不判 |
| `needs_you` | 上面这些，再加上它在等人批准一个操作、回答问题、看计划或处理对话框 |
| `everything` | 上面这些，再加上它每做完一轮，消息里带上它最后说的话（最多 1500 字） |

同一件事只提醒一次，要等被关注的 agent 下一次开始干活才会再提醒。消息标着「来自 雷达」，不用回复。提醒用咕咕当时的界面语言写（中文或英文）。

被关注的或者收提醒的那个任务不在了（归档、删除），这条关注就到此为止，自动删掉；这条路已经送到的次数还留着，以后同一对再关注会接着数。读不懂的订阅文件（比如没有 `level` 的旧格式）不会被悄悄忽略：后台报一次错，然后删掉。

## agent 怎么用

- `watch({ target, level?, stuck_minutes?, to? })`：`target` 可以写 `session:<id>`、`aid:<id>` 或 `user:<uuid>`；`level` 是上面三档之一；`to` 默认是调用者自己。没有 events 这种按事件挑选的参数。
- `unwatch({ id })`：撤掉一条关注，自己订的、或者提醒发给自己的都可以。别人替你订的提醒，你自己就能撤。
- `watching()`：列出我订的、提醒发给我的、谁在关注我，以及最近 10 条提醒。

同一个人对同一个 agent、提醒同一个人再订一次，改的是原来那一条（档位换成新的），不会多出一条。

## 限制

- 「跑完」会把被盯 agent 最后说的话（最多 1500 字）原样转给收信方，收信方可以是第三个 agent。订之前想清楚谁该看到它。
- 后台页没在跑的那段时间（咕咕关着、雷达刚装上或刚重启），发生的事会漏掉：后台起来后的第一眼只记下当时的状态，不和之前比，所以不会补报。
- `engines.gugu` 现在写的是 `>=0.2.53`。等 gugu#7023（listAgents 的 detail / failure / lastActionAt）发版以后，抬到那个版本。

- 目前只能盯这台电脑上的 agent。盯别的电脑要等咕咕的跨机器统一（PR-5）。
- 终端 agent 看不到「最后说的话」和「引擎为什么没了」，只能看到状态。
- 有人主动停掉一条正在跑的会话：咕咕 Beta 64.1（#7026）起读成「空闲 · 被打断」（`idle/plain`），雷达既不当出错、也不当跑完。更早的咕咕会把它读成出错，雷达会照常投「出错」。

## 页签

任务里打开时是以这个任务的 agent 为中心的局部图（看 1–3 层），否则是整张图。点是 agent，颜色是它此刻的状态；一条线是一条提醒走的路，从被关注的 agent 指向收提醒的人，线上的数字是这条路已经送到过几次（0 次不写）。刚送出一条时线闪一下，没送到时线变红。悬停或点开时，用一整句话说清是谁让谁在什么时候收到提醒、提醒过几次。可以拖动节点、滚轮缩放、拖背景平移。点节点后的「打开这个任务」会跳到那个任务、把雷达切到前台，要靠咕咕 #7029（已合进 dev），更早的咕咕会拦下并在页签上报错。

## 需要的能力

看到所有 agent（`agents:read:all`），给 agent 发消息（`agents:control:all`），读「跑完」时最后说的话（`agents:history:all`），给 agent 提供工具（`agents:tools`）。
